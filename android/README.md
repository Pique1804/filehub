# FileHub для Android

Код сервера находится в [server](../server/README.md). Команды ниже выполняются
из каталога `android/`.

Нативное приложение Kotlin / Jetpack Compose для файлов, фотографий и резервирования
доступных телефону фото и видео. Требуется Android 8 или новее; основной сценарий —
актуальный Filehub server и телефон владельца.

## Оформление 1.40

В настройках доступны светлая, тёмная и системная темы. Выбор сохраняется отдельно
от аккаунта и резервирования; системные панели следуют активной теме. Основные экраны
используют Golos, общую палитру и кнопки не меньше 48 dp. Нижняя навигация не перекрывает
контент; от 720 dp она становится боковой панелью. Галерея сохраняет выбор масштаба
жестом, на широких экранах использует дополнительные столбцы.

## Работа приложения

- Просмотр файлов, лента фотографий, OCR/семантический поиск, альбомы, места,
  воспроизведение видео, offline-файлы и приём файлов через Android Share.
- Выбор альбомов и папки назначения. Ручная передача и фоновые события используют
  общую долговременную очередь; WorkManager периодически подбирает пропущенные события.
  Android может отложить задачу при энергосбережении; это не гарантия мгновенной отправки.
- Докачка TUS порциями до 8 MiB, отдельные очереди фото/видео, SHA-256 и серверные
  подтверждения. Потеря финального сетевого ответа не должна создавать вторую копию.
- Сверка сохранённых копий отделена от передачи новых файлов. Проверки не старше
  24 часов считаются актуальными. Неполный ответ, ошибка сервера и остаток более
  1000 записей сохраняют ожидающую работу; WorkManager продолжает её после перезапуска.
  Подтверждённо отсутствующая копия остаётся видимой в журнале и передаётся повторно,
  если исходник ещё доступен на телефоне.
- «Освободить место» сначала сверяет серверную копию, включая переименования и
  сохранённые оригиналы редактирования, затем заново читает локальные байты и метаданные.
  Только совпавшие файлы попадают в системное подтверждение Android (до 500 за раз).
  Это подтверждение одной серверной копии, а не независимого резервного диска.
- Пароль хранится в AES-GCM envelope с неэкспортируемым ключом Android Keystore.
  Обновление переносит существующий пароль без повторного входа; plaintext удаляется
  только вместе с сохранением проверенного ciphertext. Временная ошибка миграции
  сохраняет прежний вход и повторяет попытку при следующем чтении.
- Обновлятор проверяет размер, SHA-256, packageName и versionCode APK.

Домашний HTTP нужен для существующего LAN доступа. Для внешнего доступа используйте
настроенный владельцем HTTPS адрес. Пароли, авторизацию и ключ подписи в Git не добавлять.

## Воспроизводимая сборка

Нужны JDK 17, Gradle 8.7, Android SDK 35 и build-tools. AGP, Kotlin и зависимости
закреплены в Gradle-файлах. Задайте `ANDROID_HOME` или настройте `sdk.dir`
в локальном `local.properties`.

```sh
export ANDROID_HOME="$HOME/android-sdk"
export GRADLE_BIN="$HOME/gradle-8.7/bin/gradle"
"$GRADLE_BIN" --no-daemon --max-workers=1 -PfilehubUnsigned=true :app:testDebugUnitTest :app:lintRelease :app:assembleRelease
```

Первый запуск требует загрузки зависимостей. Команда выше создаёт APK без
подписи. Для выпуска с возможностью обновления поверх официального APK
нужна подпись издателя. Ключ подписи хранится отдельно от исходников.

`scripts/release.sh /path/to/artifacts` выполняет проверки и формирует APK, SHA-256,
manifest с сертификатом подписи и перечень хешей входных исходников. Скрипт проверяет
исторический сертификат; новый APK должен устанавливаться поверх прежнего без удаления
приложения и его данных. Производственная публикация и установка выполняются отдельно.

## Проверки

```sh
# JVM: частичная/ошибочная сверка, >1000 записей, отмена, сохранность миграции пароля.
"$GRADLE_BIN" :app:testDebugUnitTest
# Только на явно выбранном изолированном emulator: настоящий Keystore и миграция SQLite.
ANDROID_SERIAL=emulator-5580 "$GRADLE_BIN" :app:connectedDebugAndroidTest
# Реальный Kotlin uploader против синтетического Go HTTP-сервера с сетевыми сбоями.
python3 tests/uploader-jvm/build.py
FILEHUB_UPLOADER_TEST_CLASSPATH="$(cat app/build/uploader-jvm/classpath.txt)" \
  sh -c 'cd ../server && go test -count=1 -v -run TestAndroidUploaderFaultRecovery .'
```

Instrumentation использует отдельные synthetic prefs/DB, но запускать его следует на
тестовом устройстве. JVM harness пересобирается из текущего `ResumableUploader.kt`;
старый JAR не считается проверкой изменённых исходников.

## Приёмка на физическом устройстве

1. Установить обновление поверх приложения: вход и прежние настройки должны сохраниться.
2. Создать отдельный тестовый альбом с новой фотографией и коротким видео; выполнить
   резервирование и открыть оба файла с сервера.
3. На тестовом крупном видео прервать Wi-Fi, вернуть его и проверить докачку без второй копии.
4. Переименовать только тестовую серверную фотографию, затем проверить её копию;
   открыть «Освободить место», проверить предложение и **отменить системное удаление**.
5. Проверить разрешения, ручную и фоновую отправку при обычных настройках энергосбережения.

Проверки на emulator/JVM не подтверждают фоновые ограничения Samsung, физический Wi-Fi,
камеру или полноту доступа к реальной MediaStore библиотеке владельца.
