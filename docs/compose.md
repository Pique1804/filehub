# FileHub в Docker Compose

Вариант для Linux x86-64 с Docker Engine 23+, BuildKit и Compose 2.17+.
Образ устанавливает системные зависимости и упаковывает готовый сервер.
Инструкция использует пакет **1.40.22**. Компиляторы и SDK для этого пути не нужны.
Последняя приёмка Compose прошла с **1.40.20**. Версию **1.40.22** проверили
на Debian 12 через [готовый Linux-установщик](installation.md).

| Установка | Подходит, когда |
| --- | --- |
| Compose | На хосте уже есть Docker и доступны обычные каталоги для архива и состояния. |
| [Готовый Linux-пакет](installation.md) | Нужна установка с systemd. Для обычных папок есть вариант `sudo ./install.sh --folders-only`. |
| [Proxmox LXC](installation.md#отдельный-диск-или-подключённая-папка) | Нужен нативный вариант с хостовым адаптером дисков. Используйте `sudo ./install.sh --proxmox CTID --restart` из готового пакета на узле Proxmox. |

## Первый запуск

1. Возьмите исходники тега `v1.40.22` и скачайте установочный архив Linux
   с файлом SHA-256 из [релиза FileHub 1.40.22](https://github.com/Pique1804/filehub/releases/tag/v1.40.22).
   Для приватного репозитория войдите в GitHub. Проверьте архив командой
   `sha256sum -c filehub-1.40.22-linux-amd64-installer.tar.gz.sha256`. Сохраните
   архив как `releases/filehub-installer.tar.gz` в корне исходников.
2. Скопируйте `.env.example` в `.env` и укажите опубликованный хеш в
   `FILEHUB_RELEASE_SHA256` для проверки архива при сборке. Укажите два раздельных каталога и
   числовые UID/GID пользователя, который имеет к ним доступ. Для запуска
   с текущим непривилегированным пользователем подставьте вывод `id -u`
   и `id -g`. Пример для пустого хранилища из корня репозитория.

   ```sh
   install -d -m 700 ./data ./state
   ```

   `FILEHUB_DATA_DIR` может указывать на уже существующую папку архива.
   Compose пробрасывает её как `/data`. Заранее проверьте доступ к нужным
   подпапкам для указанного UID/GID. Для новых файлов нужно право записи в
   папку назначения. Права и владельцы существующего архива при запуске
   сохраняются. Для внешнего диска укажите доступный после его
   монтирования подкаталог. `FILEHUB_STATE_DIR` должен указывать на отдельную
   приватную папку для SQLite, квитанций, настроек, секрета сессий и частичных
   загрузок. Начните с пустого состояния для новой установки. Оба каталога
   переживают остановку, перезапуск и пересоздание контейнера.
3. Проверьте конфигурацию и запустите.

   ```sh
   docker compose config --quiet
   docker compose build filehub
   docker compose up -d --no-build
   ```

4. Откройте `http://localhost:8080/setup`. Получите код первой настройки в
   терминале на Docker-хосте и введите его в мастере.

   ```sh
   docker compose exec -T filehub python3 -c 'import json; from pathlib import Path; print(json.loads(Path("/var/lib/filehub/setup-code.json").read_text())["code"])'
   ```

   Создайте администратора, выберите «На этом сервере», затем папку и при
   необходимости подпапки фотоленты. Для готового архива подтвердите
   подключение существующих фотографий. Их исходные файлы остаются на месте.

По умолчанию порт доступен только с Docker-хоста. Для телефона в домашней
сети укажите LAN-адрес хоста в `FILEHUB_LISTEN_ADDRESS` и тот же адрес с
портом в `FILEHUB_PUBLIC_URL`. `FILEHUB_PUBLIC_URL` — адрес, доступный
браузеру и Android, включая внешний порт при проксировании. Для HTTPS
обрабатывайте TLS на отдельном обратном прокси, передавайте исходный Host и
оставляйте порт FileHub доступным только прокси. Укажите HTTPS-адрес в
`FILEHUB_PUBLIC_URL`, тогда браузер получит cookie с атрибутом Secure.
В доверенной домашней сети можно оставить HTTP для ручной работы с файлами.
Для фоновой загрузки фото в Android 1.40.22 нужен HTTPS. Android также разрешает освобождать место после сверки копий
через HTTP, если FileHub указан частным IPv4-адресом в той же подсети Wi-Fi или
Ethernet. Для подключения через другие сети нужен HTTPS. Контейнер работает
без доступа к сырым дискам и Docker socket.
Свободное место понадобится и для оригиналов, и для базы, миниатюр и временных
передач. [Оценка ресурсов](resources.md).

## Предпросмотр документов и libvips

Для обработки изображений через libvips и предпросмотра Word, Excel и
PowerPoint задайте `FILEHUB_MEDIA_TOOLS=1` в `.env`. Пересоберите и запустите
образ командами `docker compose build filehub` и
`docker compose up -d --no-build filehub`. Вариант с дополнительными пакетами
занимает больше места. Состояние инструментов видно в настройках сервера.

## Резервное копирование и откат

- Остановите контейнер командой `docker compose stop filehub`. Создайте
  копию всего каталога состояния вместе с оригиналами и своей конфигурацией
  `.env`. Храните копию на отдельном носителе. Состояние содержит служебные
  секреты, поэтому доступ к копии должен оставаться приватным.
- Для восстановления разверните копию в новые каталоги с теми же правами.
  Укажите пути в `.env` и запустите Compose с прежним образом. Прежние
  контейнерные пути `/data` и `/var/lib/filehub` сохраняют привязку источников.
- Перед сменой версии сохраните старый локальный образ с отдельным тегом,
  исходный архив с проверенным SHA-256 и копию каталогов. Для следующего
  образа укажите свой `FILEHUB_IMAGE_TAG` и хеш архива в
  `FILEHUB_RELEASE_SHA256`. Для отката после изменения схемы базы или
  настроек используйте соответствующую парную копию состояния и оригиналов.
  Возврат прежнего образа сам по себе не откатывает состояние.

## Сервер и Android при обновлении

1. Сохраните резервную копию состояния и оригиналов. Замените
   `releases/filehub-installer.tar.gz` готовым комплектом следующего выпуска.
   Укажите его SHA-256 и новый тег образа в `.env`. Оставьте прежние пути
   `FILEHUB_DATA_DIR` и `FILEHUB_STATE_DIR`.
2. Выполните `docker compose build filehub`, затем
   `docker compose up -d --no-build filehub`. Образ берёт APK и его
   `version.json` из одного архива выпуска. Их не нужно копировать вручную
   в запущенный контейнер. У установки LXC используйте
   [подходящую процедуру обновления](upgrading.md) и комплект для этого релиза.
3. В Android откройте **Настройки → Приложение → Проверить обновление**.
   Приложение предложит установку, когда сервер отдаст APK с более высоким
   `versionCode`. Перед открытием установщика FileHub проверяет SHA-256 и
   идентификатор Android-пакета. Для обновления поверх установленной версии
   Android также проверяет подпись. После установки сравните версию в
   настройках и убедитесь, что вход и параметры резервного копирования сохранились.

## Проверка

**1.40.20.** В Compose проверены базовый запуск, подключение libvips,
предпросмотр DOCX и XLSX через LibreOffice и сохранение сеанса и файлов
после пересоздания контейнера.

**1.40.2.** 21 ноября 2026 провели более раннюю проверку с Docker Engine 29.10 и
Compose 5.8 в виртуальной машине Debian 12 x86-64 на Windows 11. Для хранения
использовали обычные каталоги Linux внутри VM.

Прошли две чистые установки с пустым каталогом и с существующим тестовым
архивом в пути с пробелом. В обоих случаях загрузили файл, проверили его
квитанцию SHA-256 и скачали побайтово совпадающий оригинал. Принудительное
пересоздание контейнеров сохранило сеанс, квитанции, загруженный файл и
содержимое существующего архива.

Проверили, что каждый контейнер запускается от непривилегированного
пользователя, использует корневую систему только для чтения и получает два
проброшенных каталога. Тестовые порты были доступны только на localhost.
