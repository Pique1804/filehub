# Разработка Filehub

## Ветки

`main` содержит исходники веба, сервера и Android, а также установщик готовых
артефактов. Установщик использует Python, Nginx и libxcrypt.
Linux определяет адрес при установке. Proxmox-адаптер вычисляет UID/GID,
передаёт постоянный сокет и рекурсивный bind. Форматирование/удаление дисков
через API не выполняется. APK сохраняет подпись предыдущих выпусков.

`feature/first-run-storage` сохраняет отдельные незавершённые Go/Android 1.41.
Они не были собраны и не должны попадать в main под видом проверенного выпуска.
Проверенная Python-установка перенесена отдельно от этих изменений.

Пройдена установка с нуля с обычной папкой и реальным Go/Nginx, а также
браузерный сценарий с claim администратора, kernel mount ext4 нового образа,
загрузкой PNG обычным интерфейсом на диск, фотолентой и миниатюрой. Перезапуск
host-сервиса, перезагрузка LXC, настоящий umount и повторный mount UUID сохраняют
аккаунт, источники и точные байты. Недоступный диск не заменяется пустой папкой.
Python-проверки проходят также с libxcrypt вместо удалённого в Python3.13 crypt.

Архив создаётся `server/scripts/package-ready.py` из проверенных готовых
бинарника и APK. Это упаковка, не Go/npm/Gradle-сборка. В архиве есть SHA256SUMS
и идентификатор исходного коммита; ключей, аккаунтов, баз и медиа нет.
Для отдельной редакции установщика можно взять артефакты опубликованного
выпуска с проверенным SHA-256 и передать `--reuse-release-artifacts`.
Упаковщик проверит связь коммитов и неизменность входов сборки. В архиве
будут записаны коммит установщика и базовый коммит программы.
Push сохраняет исходники, не обновляет установленный сервер автоматически.
Автоматических сборок по push/PR и автодеплоя нет. Ручной workflow описан ниже.
Проверка 1.40.1 выполнена на Windows и Debian 12; [отчёт](release-verification-1.40.1.md).

## Прогресс мастера

После claim браузер использует существующую подписанную сессию администратора.
`GET/POST /api/onboarding/draft` доступны только администратору незавершённой
установки; POST дополнительно проверяет origin/CSRF. Черновик в
`setup-draft.json` имеет права 0600 и привязан к session_version владельца.
Строгий список полей исключает пароль, cookies и произвольные дополнительные
поля. localStorage/sessionStorage не используются для прогресса; локально
остаётся только обычная настройка темы. Завершение из мастера проверяет текущую
сессию, повторно передавать пароль не нужно. Окончательная проверка путей и
подтверждений выполняется независимо от сохранённого черновика.

Просмотр папок ограничен 2000 непосредственных записей и восемью примерами.
Дерево загружает детей по раскрытию, без рекурсивного обхода диска.
Выбор корня диска не требует права записи на сам корень; создание новых папок
требует записи в их родителя. Монтирование, проверка UUID и запрет подмены
отключённого диска остаются обязательными.

## Каталоги и инструменты

Команды сервера выполняются из `server/`, команды Android — из `android/`.
Скрипты находят корень своей части по собственному пути. Для интеграционной
проверки uploader Android его classpath нужно задавать абсолютным путём.
Именованные установки (`--name`) используют отдельную копию кода мастера в
`/opt/filehub-installers/NAME`; стандартная установка сохраняет `/opt/filehub-installer`.

Требования и команды описаны в [`server/BUILD.md`](../server/BUILD.md) и
[`android/README.md`](../android/README.md). Gradle Wrapper в исходниках отсутствует:
нужен отдельно установленный Gradle 8.7. Ключ подписи, SDK и `local.properties`
не входят в репозиторий.

Сборку и сквозные проверки выполняйте в выделенной среде с тестовыми
данными. Проверяйте собранные артефакты перед публикацией.

## Проверка следующего релиза

`.github/workflows/verify-release.yml` запускается только вручную через
`workflow_dispatch`. Push и pull request не вызывают сборку. Само добавление
workflow не означает разрешения его запустить.

При разрешённом запуске GitHub проверяет точный SHA на своих временных машинах:
Python-тесты, сборку Svelte, Go-тесты/vet, Android unit-тесты/lint и unsigned APK.
Ключ установленного Android-приложения остаётся у владельца. APK из CI нельзя
считать готовым обновлением: его нужно подписать прежним ключом, проверить
сертификат/версию/хеш и прогнать изолированную установку с новым сервером.
Workflow не публикует релиз, не разворачивает приложение и не меняет видимость
репозитория. Фикстуры EXIF и межъязыкового uploader требуют отдельных прогонов;
пропущенный тест не считается проверенным сценарием.

## Карты и веб-медиа

`feature/maps-and-web-media` готовит 1.40.2 отдельно от незавершённой 1.41.
[Поведение и зависимости](maps-and-media.md). Новый сервер сохраняет прежний
Android API; общий стиль карты требует сервер 1.40.2. Карта использует отдельный
same-origin worker из пакета MapLibre, а не внешний CDN. На Android нужны SDK35,
AGP8.6.1 и Kotlin2.0.21/Compose plugin; Gradle8.7 и JDK17 сохраняются.
