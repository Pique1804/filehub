# Проверка Filehub 1.40.2

Сервер/веб и Android собраны на отдельно разрешённом Windows-хосте. Сборочные
процессы и их потомки ограничены общим Job Object: 6 ГБ RAM и 25% CPU.
Основной установленный Filehub этой проверкой не обновляется.

## Результаты

- npm: четыре теста идентичности файлов, группировки дат, геометок и назначения
  возобновляемых загрузок; production Vite build.
- Go: test executable собран на Windows для Linux, полный набор запущен отдельно
  с пределом 768 МБ; `go vet` пройден на Windows.
- Android: 20 unit-тестов без пропусков и ошибок, `lintRelease` без errors/fatal,
  `assembleRelease` с минификацией R8. Остаются 44 предупреждения lint.
- APK: versionName1.40.2, versionCode52, сертификат установленного приложения
  сохранён: `15fc6661c4196a4732d7a055140b9d01b697c8fc15ef169617070ba953dff5b2`.
- Сборочный манифест сервера сверяется побайтно с исходниками, включая lockfile.
  `.gitattributes` фиксирует LF для воспроизводимости Linux/Windows.
- Python-мастер сохраняет совместимость с готовым APK1.40.2. Архив установщика
  содержит готовые бинарник и APK; пользователю не требуется компиляция.

## Браузерная приёмка

Изолированный сервер с синтетической библиотекой из 721 снимка/видео, отдельной
базой и тестовым администратором. Производственные аккаунты, cookies, фотографии
и секрет службы не использовались. Сервер ограничен 384 МБ, браузер — 768 МБ.

Проверены реальные сценарии:

1. Четыре страницы API по курсору; в DOM около 20 карточек вместо всей коллекции.
2. Декодирование фото, увеличение, переход к следующему снимку и Escape.
3. OCR через новую веб-форму и настоящий серверный поисковый endpoint.
4. Клики по отрисованным группам на карте, выбор области, просмотр снимков,
   фильтр дат и сброс. Подложка и точки работают из production-бандла.
5. Настоящий MP4 декодируется в PhotoSwipe с обычными элементами управления.
6. Пять файлов переданы через TUS с точными байтами; одновременно не более
   трёх PATCH-запросов. Отдельно проверены пауза и продолжение.
7. Ошибка передачи и успешный повтор через кнопку очереди.
8. Один и тот же локальный файл в другой папке создаёт отдельную передачу.
9. Фотолента при ширине 390px и тёмная карта без горизонтального переполнения.
10. Перезагрузка страницы и повторный выбор файла продолжают загрузку с 8 МиБ;
    итоговый SHA-256 совпадает с локальным файлом.

В завершённом браузерном прогоне нет JavaScript runtime errors. Проверка выявила
неработавший worker в первоначальном бандле MapLibre; итоговый бандл содержит
отдельный worker на том же origin и прошёл клики по реальным группам снимков.

## Репетиция обновления

На отдельной прямой systemd-установке с синтетическими данными выполнены реальное
обновление готовых файлов 1.40.1 → 1.40.2 и откат. Исходная cookie остаётся
действительной, источник и байты файла сохраняются. Аккаунт, созданный после
обновления, остаётся в базе после отката. Проверены также versionCode52 и точный
SHA-256 подписанного APK, выдаваемого через защищённый API приложения.

## Ограничения

Физический Android-телефон не подключён. Нельзя считать проверенными плавность
карты на конкретном устройстве, GPU-драйвер, жесты и возобновление после ухода
приложения в фон. Их нужно принять на телефоне после установки подписанного APK.
Android SDK и unit-тесты не заменяют эту проверку.

Нагрузка фототеки владельца на новой версии отдельно не измерена. Браузерная
приёмка использует синтетические медиа и геометки. Формат фото-папок, аккаунты
и схема базы не меняются; CLIP не устанавливается и не включается.

Универсальный подписанный APK занимает около 53 МБ: MapLibre включает нативные
библиотеки четырёх архитектур. Размер архива не является измерением RAM на
телефоне. Тайлы и шрифты требуют сети или настроенного собственного провайдера.
