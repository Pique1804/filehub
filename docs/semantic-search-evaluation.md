# Локальный поиск по описанию

В FileHub уже есть три вида поиска. Индекс SQLite FTS5 ищет названия
файлов и текст документов. OCR добавляет текст на снимках и скриншотах.
Фото с сохранённым вектором можно искать по схожести с текстовым запросом
через CLIP. Go-сервер хранит его вектор и рассчитывает сходство. Модель
запускается отдельно. [Как устроен CLIP в FileHub](../server/clip-sidecar/README.md)

## Эксперимент на CPU

В наборе 12 вымышленных документов, 12 карточек вымышленных фотографий
и 16 запросов. Размечен один релевантный результат для каждого запроса.
Для текста фотографий используются вымышленные результаты OCR, а для
E5 также заданы ручные подписи. Подписи проверяют качество поиска по
готовому описанию. Скорость и качество генерации описаний этим тестом
не измерялись. Поиск CLIP по пикселям отдельно проверен на 12 синтетических
иллюстрациях тех же сцен.

Базовый вариант повторяет поиск по всем словам с префиксами и ранжирование
BM25 в текстовом индексе FileHub. Второй вариант добавляет
multilingual-e5-small INT8 и поиск по косинусному сходству. Тест запущен
на CPU с одним потоком ONNX Runtime и лимитами 768 МиБ и 50% одного CPU.
[Карточка модели E5](https://huggingface.co/intfloat/multilingual-e5-small)

| Материалы и язык | Хотя бы один релевантный результат в первых пяти, FTS | E5 |
| --- | ---: | ---: |
| Документы, русский | 1/4 | 4/4 |
| Документы, английский | 1/4 | 4/4 |
| Фотографии по OCR или подписи, русский | 1/4 | 4/4 |
| Фотографии по OCR или подписи, английский | 0/4 | 4/4 |

Для тех же восьми запросов по изображениям использовалась Q4 ONNX-конверсия
весов LAION ViT-B/32. CLIP нашёл нужную сцену в первых пяти результатах
для 3/4 русских и 4/4 английских запросов. На русском запросе про собаку
в снегу первым оказался рисунок хлеба, верный результат был четвёртым.
Запрос про торт со свечами пропустил нужную иллюстрацию.
[Веса CLIP](https://huggingface.co/laion/CLIP-ViT-B-32-laion2B-s34B-b79K), [ONNX-конверсия](https://huggingface.co/onnx-community/CLIP-ViT-B-32-laion2B-s34B-b79K-ONNX)

Запрос про ремонт кухни поставил инструкцию по монтажу раковины выше
нужной сметы. Запрос «как поливать теплицу» поставил смету по кухне выше
инструкции по поливу. E5 дал правильный первый результат для 14 из 16
запросов. Размер выборки и ручные подписи не позволяют переносить эти
проценты на большую медиатеку.

| Измерение | FTS | E5 INT8 |
| --- | ---: | ---: |
| Индексация 24 записей после запуска | 0,25 мс | 387 мс |
| Медиана запроса | 0,16 мс | 7,78 мс |
| Самый медленный из 16 запросов | 0,32 мс | 95,1 мс |
| Индекс в опыте | 24 КиБ SQLite | 36 КиБ векторов |

E5 загрузился примерно за 2,27 с. Пиковая память процесса составила 464 МиБ.
Модель занимает 113 МиБ, токенизатор 16,3 МиБ. Вектор float32 занимает
1,5 КиБ на запись, без учёта метаданных и базы. Время запроса измерено внутри
процесса без сети, OCR и доступа к файлам. Скорости индексации и запросов
для крупной коллекции отдельно не измерялись.

CLIP обработал 12 иллюстраций за 2,29 с, сохранив 24 КиБ векторов. Пиковая
память составила 388 МиБ. Медиана запроса 390 мс включает прогон ветви
изображения в совместном ONNX-графе. В FileHub для запроса используется
отдельный текстовый обработчик, его задержка этим числом не измерена.

## Как встроить после проверки на большем наборе

Для документов можно добавить необязательный локальный индекс с E5 по
извлечённому тексту. Сохранить совпадения FTS для имён, артикулов и точных
формулировок, затем объединять выдачу по рангу. Для фотографий оставить
CLIP для изображений и OCR для надписей. Добавление готовых описаний имеет
смысл проверять отдельно, включая стоимость их получения и ошибки модели.

Разрешённые пути должны отбираться до ранжирования и подсчёта. Существующий
сервер использует видимую профилю фотоленту для отбора результатов CLIP и
ограничения по источнику и папке в SQL для FTS. Рабочий процесс для E5
должен получать текст документов и OCR только из разрешённых к индексации
источников. Поисковому клиенту нужны только результаты его профиля.

На временном FileHub тестовый профиль видел свой результат при top-1,
даже когда снимок в закрытой папке был ближе к запросу. После отзыва
доступа повторный запрос под тем же профилем вернул пустую выдачу при
сохранённом в базе векторе.

Модель и векторы можно хранить отдельно от оригиналов. Для обновляемого
индекса хранить идентификатор источника, путь, ревизию и версию модели.
При изменении файла старый вектор исключать до пересчёта. При удалении
удалять запись и её кэш. При отзыве доступа повторно проверять права на
каждый запрос к существующему индексу. Обработка пачками с ограничением
потоков и паузой в очереди позволяет остановить смысловую индексацию,
сохранив текстовый поиск. Облачные API для этого варианта не нужны.

## Повторить измерения

В тесте использовались Python 3.11, numpy 1.26.4, onnxruntime 1.20.1 и
tokenizers 0.21.0. Веса `onnx/model_qint8_avx512_vnni.onnx` и
`tokenizer.json` взяты из ревизии
[`614241f`](https://huggingface.co/intfloat/multilingual-e5-small/tree/614241f622f53c4eeff9890bdc4f31cfecc418b3).
После получения файлов сам тест выполняется без сети.

```sh
python server/clip-sidecar/benchmark_search.py \
  --model /path/to/model_qint8_avx512_vnni.onnx \
  --tokenizer /path/to/tokenizer.json \
  --revision 614241f622f53c4eeff9890bdc4f31cfecc418b3
```

Для иллюстраций дополнительно использовался Pillow 11.3.0. Файлы
`onnx/model_q4.onnx`, `tokenizer.json` и `preprocessor_config.json`
взяты из ревизии [`de693d0`](https://huggingface.co/onnx-community/CLIP-ViT-B-32-laion2B-s34B-b79K-ONNX/tree/de693d0c5a5b263ae94ece9bf751e0cda14305d8).

```sh
python server/clip-sidecar/benchmark_clip_images.py \
  /path/to/model_q4.onnx /path/to/tokenizer.json /path/to/preprocessor_config.json
```
