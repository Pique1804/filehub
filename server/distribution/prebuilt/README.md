# Filehub: установка готового сервера и APK

Пакет запускает проверенные готовые сервер и Android APK одной версии. Go/npm/Gradle
не требуются. Мастер и управление дисками используют Python 3.11+ и libxcrypt,
включая Python 3.13 без удалённого модуля `crypt`. Нужен Linux с systemd.
Готовый пакет содержит бинарник x86-64; установщик проверяет архитектуру CPU.

## Установка из архива

```sh
tar -xzf filehub-*-linux-amd64-installer*.tar.gz
cd filehub
sudo ./install.sh
```

Адрес определяется по сети этой машины и печатается в конце. При необходимости:
`sudo ./install.sh --url http://YOUR-SERVER:8080`. Пакеты Debian/Ubuntu
устанавливаются готовыми, с ограничением памяти/CPU. Архив проверяет SHA-256
своих файлов, включая сервер/APK, перед установкой. Ключей подписи и аккаунтов
в нём нет. Установщик печатает закрытую ссылку с кодом первичной настройки; пароль аккаунта
задаёт сам владелец в браузере.

Для отдельного уже созданного Debian/Ubuntu LXC команда выполняется на Proxmox:

```sh
sudo ./install.sh --proxmox CTID --restart
```

Замените `CTID` своим номером. Установщик сохраняет конфигурацию, вычисляет
отображённые UID/GID, подключает только выделенный каталог дисков и сокет,
устанавливает зависимости в выбранном CT и при необходимости перезапускает
именно его. Рекурсивный bind сохраняет вложенные диски при перезагрузке.
Подключение адаптера к существующей установке сохраняет аккаунты, базу, оригиналы
и имена источников. Сам установщик новой системы существующую базу не переносит;
для прямого сервера 1.40 используйте [обновление и откат](../../../docs/upgrading.md).
Изменения требуют доверия к root-установщику; приватные резервные копии остаются
на соответствующем сервере. Другие контейнеры автоматически не меняются.

## Из исходников установщика

Предоставьте опубликованный бинарник и `app/app.apk`, `app/version.json`:

```sh
sudo bash server/scripts/install-ready.sh --install-dependencies \
  --binary /absolute/path/to/filehub --app-dir /absolute/path/to/app
```

На обычном Linux сервис дисков включается автоматически. Если нужны только
папки, явно передайте `--folders-only`. В контейнере установка может начаться
с обычной папки без host-сервиса. «Отдельный диск» в мастере откроет помощь:
Shell узла Proxmox, номер CT, готовая команда с проверяемым пакетом подключения,
проверка связи и выбор диска. Установщик не выдаёт отсутствие host-сервиса
за возможность монтировать устройства. Произвольный Docker без systemd/хостового проброса
этот установщик не настраивает.

Новая установка отказывается перезаписывать существующую конфигурацию,
проверяет порты, архитектуру, APK и наличие bcrypt. Внутренний порт Go закрыт
от LAN отдельным правилом nftables, управляемым своей службой. Чужие firewall
таблицы не очищаются. Открывается только веб-вход. Для внешнего доступа
владелец настраивает HTTPS или VPN; портов на роутере установщик не открывает.

## Первый запуск

1. Создайте администратора. Аккаунт сохраняется до выбора дисков, поэтому
   прерванный мастер можно продолжить после входа и перезагрузки.
2. Используйте обычную папку `Main` или подключите готовый HDD/SSD/USB в этом
   же мастере. После подключения выберите диск и добавьте именованный источник.
3. Укажите фото-папки внутри источников. Это те же оригиналы, не второе
   хранилище. Существующие фото включаются только после подтверждения.
4. Завершите настройку и откройте `/connect`: адрес именно этого сервера,
   APK, QR и фактическая папка назначения автозагрузки.

Android 1.40 требует вставить адрес сервера на экране входа, затем выбрать
альбомы телефона и папку назначения из инструкции. Непроверенного APK 1.41
пакет не содержит. `Main/Photos` по умолчанию пуст; чужие фотографии не добавляются.

После установки `/storage` позволяет добавлять источники и фото-папки.
Сохранение делает приватную копию конфигурации и перезапускает только Go;
передачи с докачкой могут продолжиться. Имена и пути используемых источников
закреплены. При потере диска файловый сервер останавливается, настройки
доступны; пустая папка вместо диска не создаётся. При возврате UUID запуск
повторяется автоматически. Диски не форматируются и не удаляются.

## Подтверждённые проверки

- Полная установка с нуля с обычной папкой, аккаунтом, TUS, PNG и фотолентой.
- Кнопка подключения в браузере выполняет настоящий kernel mount ext4.
- Обычный веб-загрузчик сохраняет фото на этот диск; оригинал и миниатюра проверены.
- Сохранение дополнительных источников/областей фото, совместимость сессий Go.
- Перезапуск host-сервиса, настоящая перезагрузка LXC, umount и повторный mount
  сохранённого UUID сохраняют аккаунт, имена источников и точные байты файла.
- Недоступный диск даёт 503 для файлов, оставляет настройки и не подменяется
  новой папкой. Проверены CSRF, вход администратора, traversal/ссылки и ширина390px.

Для безопасной приёмки использован новый 256-МБ файл-образ ext4 на отдельном
стенде, не личные физические диски. FAT/exFAT/NTFS/Btrfs/XFS зависят от драйверов
ядра и отдельно не проходили этот сценарий. Перезагрузка хоста Proxmox целиком
не выполнялась; проверялись перезагрузка LXC и восстановление хостового сервиса.

Ориентир: 2 vCPU, 2 ГБ RAM, 8–12 ГБ ОС/приложение плюс оригиналы, индекс и кэш.
Лимиты и измерения: [resources.md](../../../docs/resources.md).
